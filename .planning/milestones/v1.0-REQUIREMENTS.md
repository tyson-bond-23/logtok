# Requirements Archive: v1.0 MVP

**Archived:** 2026-04-28
**Core Value:** Engineers can diagnose production log errors through Claude Code without revealing any sensitive information

## v1 Requirements — All Complete

### Detection

- [x] **DET-01**: User can detect and tokenize credentials (API keys, tokens, passwords, connection strings)
- [x] **DET-02**: User can detect and tokenize PII (emails, IP addresses, usernames, phone numbers)
- [x] **DET-03**: User can detect and tokenize infrastructure details (hostnames, file paths, internal URLs, ports)
- [x] **DET-04**: User can preview what would be tokenized before sending (dry-run mode)
- [x] **DET-05**: User can configure detection rules (enable/disable categories, add custom patterns)

### Tokenization

- [x] **TOK-01**: Same sensitive value always produces the same token (deterministic)
- [x] **TOK-02**: Tokens are category-prefixed for LLM context (`[IP_001]`, `[KEY_001]`, `[EMAIL_001]`)
- [x] **TOK-03**: Token mappings stored in encrypted local store (AES-256-GCM)
- [x] **TOK-04**: Token store persists across sessions and can be reused
- [x] **TOK-05**: User can tokenize structured JSON logs preserving structure
- [x] **TOK-06**: User can tokenize unstructured/plain text logs

### Diagnosis

- [x] **DIA-01**: User can send tokenized logs to Claude Code for diagnosis (via CLAUDE.md instruction block)
- [x] **DIA-02**: Claude's response is de-tokenized back to real values automatically
- [x] **DIA-03**: User receives bullet-point summary (root cause, affected components, suggested fix)
- [x] **DIA-04**: User receives detailed markdown report
- [x] **DIA-05**: User can copy tokenized output to clipboard for manual use with any LLM

### Infrastructure

- [x] **INF-01**: Single binary, zero runtime dependencies
- [x] **INF-02**: Cross-platform (Windows, macOS, Linux, ARM) — CI/CD release workflows configured
- [x] **INF-03**: Block-based processing for large files (bounded memory usage)

## Notes

- **TOK-02** format changed from `[TOK_IP_001]` to `[IP_001]` during design (CONTEXT.md D-02). Shorter format improves LLM context efficiency.
- **DIA-01** implemented as CLAUDE.md instruction block rather than direct API call. This is more flexible (works with any LLM, no API key needed) and validated during UAT.
- **DIA-03/DIA-04** output format determined by Claude Code's response, not by logtok. The detokenize command restores real values in whatever format Claude produces.
