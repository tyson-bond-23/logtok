# Milestone v1.0: MVP

**Status:** SHIPPED 2026-04-28
**Phases:** 1-3
**Total Plans:** 9

## Overview

Deliver a CLI tool that tokenizes sensitive data out of logs, sends sanitized logs to Claude for diagnosis, and de-tokenizes the results -- all without secrets ever leaving the local machine.

## Phases

### Phase 1: Core Tokenization Engine
**Goal**: User can feed a log file into the tool and get back a tokenized version with deterministic, category-prefixed placeholders -- processing large files without excessive memory usage
**Depends on**: Nothing (first phase)
**Requirements**: INF-01, INF-03, TOK-01, TOK-02, TOK-05, TOK-06
**Plans**: 3 plans

Plans:
- [x] 01-01-PLAN.md — Scaffold Rust project, CLI argument parsing, error types
- [x] 01-02-PLAN.md — Detection engine, deterministic token map, JSON and plain text tokenization
- [x] 01-03-PLAN.md — Block processing pipeline, compaction, progress bar, end-to-end wiring

### Phase 2: Detection & Token Store
**Goal**: User can detect all categories of sensitive data (credentials, PII, infrastructure) with configurable rules, preview what would be tokenized, and have mappings persist encrypted across sessions
**Depends on**: Phase 1
**Requirements**: DET-01, DET-02, DET-03, DET-04, DET-05, TOK-03, TOK-04
**Plans**: 3 plans

Plans:
- [x] 02-01-PLAN.md — Expand detection to 19 categories, config-driven architecture, serializable TokenMap
- [x] 02-02-PLAN.md — TOML config module and AES-256-GCM encrypted token store module
- [x] 02-03-PLAN.md — CLI integration (--dry-run, --reset-store, --config), processor wiring, end-to-end tests

### Phase 3: Diagnosis & Delivery
**Goal**: User can take Claude Code's tokenized diagnosis and de-tokenize it back to real values, with polished CLI UX and cross-platform binary distribution
**Depends on**: Phase 2
**Requirements**: DIA-01, DIA-02, DIA-03, DIA-04, DIA-05, INF-02
**Plans**: 3 plans

Plans:
- [x] 03-01-PLAN.md — CLI restructure to subcommands, detokenize engine, clipboard support, progress bar enhancement
- [x] 03-02-PLAN.md — CLAUDE.md token-aware instruction block, README.md documentation
- [x] 03-03-PLAN.md — GitHub Actions CI and cross-platform release workflows

## Milestone Summary

**Key Accomplishments:**
1. Block-based tokenization engine handling JSON and plain text logs with bounded memory
2. 19-category sensitive data detection with configurable rules and custom patterns
3. AES-256-GCM encrypted token store with Argon2id key derivation for session persistence
4. Full tokenize-diagnose-detokenize round-trip workflow
5. Clipboard integration and cross-platform CI/CD release pipelines
6. Claude Code token-aware diagnosis via CLAUDE.md instruction block

**Key Decisions:**
- Language: Rust (performance, single binary, memory safety)
- Block-based processing (future-proof for streaming)
- Encrypted local token store (AES-256-GCM + Argon2id)
- Claude Code integration via static CLAUDE.md (no plugins/MCP needed)
- Token format: `[CATEGORY_NNN]` (dropped `TOK_` prefix for readability)

**Issues Resolved:**
- UTF-8 panic in truncate_example (CR-01)
- Unsigned integer underflow in purge_expired (WR-02)
- Regex recompilation per detokenize call (WR-04)
- Unsafe env var mutation in store tests (WR-05)

**Technical Debt:**
- Compiler warnings for unused public API items (intentional — library exports for future use)
- DIA-01 (Claude API integration) implemented as CLAUDE.md instruction block rather than direct API call
- PATH regex only matches Unix-style paths, not Windows paths
