Add `reqwest = { version = "0.12", features = ["blocking"] }` to `[dev-dependencies]` in Cargo.toml if not already present (check first). Use blocking reqwest for simplicity in tests, or use tokio test runtime.

**Test structure:**

Use a shared helper function that starts the server on port 0 (OS assigns random port) and returns the base URL. Since `ui::start_server` opens a browser and blocks, create a test-specific server start function that skips browser open.

Alternatively, directly build the router and use `axum::serve` with a `TcpListener` bound to port 0:

```rust
use axum::Router;
use tokio::net::TcpListener;
use std::sync::Arc;
use tokio::sync::{oneshot, Mutex};

async fn start_test_server() -> (String, oneshot::Sender<()>) {
    // Set LOGTOK_KEY for test
    std::env::set_var("LOGTOK_KEY", "test-key-for-integration-tests-0123456789abcdef");
    
    let (shutdown_tx, shutdown_rx) = oneshot::channel();
    let state = Arc::new(logtok::ui::AppState {
        shutdown_tx: Mutex::new(None), // Don't use shutdown for tests
        session_key: "test-key-for-integration-tests-0123456789abcdef".to_string(),
    });
    
    let app = logtok::ui::routes::build_router(state);
    let listener = TcpListener::bind("127.0.0.1:0").await.unwrap();
    let port = listener.local_addr().unwrap().port();
    
    tokio::spawn(async move {
        axum::serve(listener, app)
            .with_graceful_shutdown(async { let _ = shutdown_rx.await; })
            .await
            .unwrap();
    });
    
    (format!("http://127.0.0.1:{}", port), shutdown_tx)
}
```

Note: For this to work, `AppState`, `routes::build_router`, and the handler modules need to be accessible from integration tests. This may require adding `pub` visibility to `ui` module internals or exposing a test helper. If the `ui` module's internals are private, create a `pub fn build_test_server()` function in `src/ui/mod.rs` that returns a `Router` -- add this to mod.rs if needed (acceptable modification since Plan 05 is in Wave 3, after all other plans complete).

Alternatively, make the test simpler by just testing the CLI binary with `assert_cmd`:

```rust
#[test]
fn ui_starts_and_responds() {
    // Start logtok ui in background, wait for port message, make HTTP request
    // This is harder to test reliably, so prefer the direct router approach
}
```
