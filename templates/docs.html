logtok Documentation

Version {{ version }} — Tokenize sensitive data out of log files for safe AI analysis.

Getting Started

Install

cargo install logtok

Quick Start

Three steps to safely diagnose production log errors with AI:

1
Tokenize — Remove sensitive data from your logs 
logtok tokenize server.log -o safe.log
2
Analyze — Send the tokenized safe.log to Claude Code (or any LLM) for error diagnosis. All sensitive values have been replaced with safe tokens like [IP_001] and [KEY_002].
3
De-tokenize — Restore real values in the AI response 
logtok detokenize response.txt
Token mappings are stored in an encrypted local store (AES-256-GCM). Sensitive data never leaves your machine.

Overview

logtok removes credentials, PII, and infrastructure details from application logs, replacing them with deterministic tokens. After AI diagnosis, de-tokenize the response to restore real values — without ever exposing the original secrets.

Key features:

  • 19 detection categories: IPs, API keys, emails, JWTs, PEM certificates, and more
  • Encrypted token store (AES-256-GCM + Argon2id key derivation)
  • Deterministic tokens — same value always maps to the same token
  • Block-based processing for large files (GB-scale)
  • Cross-platform single binary (Windows, macOS, Linux, ARM)
  • Configurable detection via .logtok.toml

Token Categories

logtok detects and tokenizes sensitive data across 19 categories. Each token follows the format [CATEGORY_NNN], where CATEGORY is an uppercase label and NNN is a counter. The same real value always maps to the same token within a session.
